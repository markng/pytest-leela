Could Numba make Leela faster?

Short assessment · Source inspection and existing run logs, not a CPU profile or Numba benchmark.

Bottom line: potentially, but not as a drop-in. There is confirmed repeated AST work worth investigating. We have not yet measured its runtime share or demonstrated any Numba speedup. Profile first; try doing less work before compiling it faster.

What is confirmed

  • Repeated tree work: each mutated module load in MutatingLoader.exec_module performs parse → traverse/mutate → fix locations → compile.
  • Not a ready-made Numba kernel: this operates on Python ast.AST objects through a dynamic visitor. Numba can accelerate typed tree/graph algorithms, but this machinery would need adaptation—perhaps a compact typed representation—and conversion/JIT costs would need to pay for themselves.
  • Session timings are broad: they include module eviction, pytest collection, plugins, fixtures, imports/AST work, test bodies and cleanup. Leela already has selection/preparation optimisations; this is not a claim that nothing is cached.

What the saved run tells us

The historical, interrupted 24 October self-check—not the currently running validation—recorded:

Interpretation: the median is much lower than the mean (~8 seconds), indicating a long tail of expensive sessions. About 40% of reported session time was for mutants targeting type_extractor.py, and 21% for runner.py. Those are promising investigation groups, not function-level CPU hotspots.

Likewise, “96% inside pytest sessions” does not mean “96% in test bodies” or rule out expensive tree processing. Self-mutation tests also exercise Leela and mypy; another application's workload may differ.

Recommended next step

  1. Measure phases: separate parsing, traversal, location fixing and compilation from collection, fixtures, test bodies and cleanup. Compare cold/warm runs on a small representative workload.
  2. Compare avoiding work: investigate parse/compiled-code caching and indexed mutation paths while preserving isolation between mutants. Do not assume AST copying is cheaper than parsing.
  3. Then consider Numba: prototype only if a substantial CPU-bound, Numba-compatible kernel remains. Measure end-to-end time, including conversion and JIT startup.

No Numba installation, performance implementation or new profiling campaign was performed for this assessment. The existing benchmark mode runs four complete configurations; it is not the lightweight phase profile needed here.
